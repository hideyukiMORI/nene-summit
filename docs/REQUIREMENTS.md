# 要件と意思決定 — NeNe Summit

## 状態の区別

- **確定依頼**: このプロジェクトについて施主が明示したこと。
- **初期方針**: 兄弟を参考に今回の初期設定で採用した技術・運用方針。施主の発言ではない。
- **設計案**: 実装の出発点。調整可能で、変更理由を ADR に記録する。
- **未決**: 数値や仕様を実測・試作で決める。勝手に「施主決定」と書かない。

## 未決事項と推奨の扱い

- **人の操作**: Bolt と同様の割り込み操作は候補。スクリーンセーバーの MVP 後に扱う。入力型は最初から共有可能に設計する。
- **面数・演出量・キャスト・セリフ数・テーマ数**: 兄弟の「4 名・50 本・12 テーマ」を確定要件としてコピーしない。最初は 1 名・1 テーマ。
- **難易度・残機・スコア・記録保存**: 登山との相性を試作で判断。失敗回数・到達高度・登頂が候補。敵やボスは初期スコープ外。
- **固定小数点の倍率、tick rate、ダッシュ時間、ジャンプ猶予、カメラ**: 倍率と速度は設計判断で [ADR 0005](adr/0005-playable-climb.md) の `MotionPolicy` に置いた。施主の実測による確定ではない。秒は合成ルート。カメラは未決。描画の間引きでゲーム速度を変えない。
- **1 遠征の長さ**: まず 2〜5 分を評価目標として測る。保証や確定要件ではない。
- **配布物・インストーラ・Swift の具体的な版**: P0 / P5 で検証して固定する。

## テストする不変条件

同じ seed・入力列・設定から同じ状態列。地形への埋まりや高速ダッシュのすり抜けなし。
ダッシュ残数は定義域内、回復条件以外で増えない。壁蹴りは有効な接触だけから起きる。
復帰で必要な状態がリセットされ、部屋の到達済み情報が定義どおり保持される。
AI の先読みで現実の状態や乱数列が変わらない。描画・端末サイズがゲーム結果を変えない。
上限 tick を持つ試行が終了状態に到達し、無入力で次の遠征が始まる。
