# アーキテクチャ憲章

一つの意味には一つの正典経路を設け、可能な規則は機械で守る。
以下は初期採用の規範。強制状態は [QUALITY_GATES.md](QUALITY_GATES.md) のみが管理する。

| ID | 規範 |
| --- | --- |
| ARC-001 | 物理・衝突・失敗・復帰・部屋クリア・遠征終了は Core に各一経路。別実装を併設しない |
| ARC-002 | target と import の直接依存は [PROJECT_LAYOUT](PROJECT_LAYOUT.md) の方向だけ。推移的依存を直接 import しない |
| ARC-003 | Core の step は状態・入力・明示した乱数状態から次の状態と出来事を作る。座標・速度は整数固定小数点 |
| ARC-004 | Engine は入力だけ返す。先読みは Core の step を複製状態に適用し、本番状態・本番乱数を消費しない |
| ARC-005 | 時計・外部乱数による seed・環境・引数・保存は合成ルートが所有する。Core / Engine / Render はそれらを知らない |
| ARC-006 | Render は状態と表示設定からセル格子を返す。Terminal はセルの ANSI 変換と端末資源管理。ゲーム規則を置かない |
| ARC-007 | 入力取得・固定刻みの実行・描画は一本の同期ループ。並行性の仕組みを追加しない |
| ARC-008 | 人の入力を追加しても Core の同じ Input / step を使う。入力主体の切替は合成ルートに置く |
| ARC-009 | 状態は値型を中心に所有者を一つにする。公開された参照の副作用で状態を書き換えない |
| ARC-010 | 期待される失敗は閉じた結果型で表す。黙って成功・空値に置き換えない |
| ARC-011 | 不要な抽象化・将来用 target・Legacy/V2 の並行経路を作らない |

色・カメラ・演出は Render の責務。見た目の乱数はゲームの乱数と分離し、描画の有無でゲームが変わらないようにする。
固定刻みの蓄積、遅延時の追いつき上限と過負荷の扱いは P3 の ADR で定義する。
