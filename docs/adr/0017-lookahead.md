# ADR 0017 — 案内は advance の複製で短く先を見る

Status: accepted
Date: 2026-11-01
Issue: #31
Scope: 設計案。施主の確定要件ではない。先の長さと比較の重みは施主の指定ではない。

## 背景

案内は足もとのマスを見て、右へ歩くか跳ぶかを決めていた。
その先で落ちるか届くかは、本番の `advance` を複製せずに判断していた。
憲章は、先読みを Core の step の複製に限り、本番の状態を消費しないと定める。

## 判断

案内の入力は `Lookahead` が選ぶ。候補は少ない。
各候補は、複製した状態へ `SummitState.advance` を短いあいだ適用して比べる。
本番の状態は、選んだ入力で一度だけ進む。別の速度、別の衝突、外部の乱数は足さない。
落ちた候補は棄てる。届いた候補を優先する。高さと、頂上への横の近さで残る候補を比べる。
先の長さは `Lookahead` に置く。この文書へ写さない。

## 比較した案

マスの種類だけで跳び方を決める案は採らない。先の結果が `advance` と分かれうる。
学習や外部の探索へ渡す案は採らない。状態の経路が二つになる。
本番の状態を先読みで進めて戻す案は採らない。戻し忘れが登頂を変える。

## 影響と検証

[ADR 0006](0006-unattended-retry.md) の「先読みは入れない」は、本決定が置き換える。案内が入力だけを返すことは残る。
Swift Testing が、先読みのあと本番の状態が同じであること、棘へ歩くより落ちない候補を選ぶこと、
無入力で二部屋を登頂することを見る。
この案内が、作った二部屋以外を解く保証はない。seed の到達率は未記録。
さらに先の部屋、動く床、カメラの補間、テーマ、配布は残る。
