# ADR 0011 — 実機の入力はローカルファイルに残す

Status: accepted
Date: 2026-11-01
Issue: #17
Scope: 設計案。施主の確定要件ではない。

## 背景

方向を押したジャンプは走る速さで出るようにした。実機では、その前よりは良いが、合格できる操作感ではない。
入力バイトの記録が無いので、スペースと `a` / `d` が同じ読みで届いたのか、空中の速度が案内に置き換わったのかが残っていない。

## 判断

起動のたびに、ローカルファイルへその場の入力と速度を書く。既定のパスは Terminal の `PlayTrace` が持つ。この文書へ写さない。
環境変数 `NENE_SUMMIT_TRACE` が `0` のときは書かない。`1` または空なら既定のパス。それ以外はそのパス。
ファイルは起動ごとに作り直す。権限は持ち主だけ。開けないとき、または書けないあとは、記録をやめて遊びは続ける。
地面で、届いたバイトも人の入力も無く、空中でも壁でもない tick は書かない。
一行は、ミリ秒、tick、バイト、解釈、押下、人の `Input`、モード、人か案内か、変化の前後の位相、セル、横速度、縦速度、残りのダッシュ。
速度の読み取りは `SummitState` の関数。状態を進めるのはこれまでどおり `advance` だけ。
ネットワークへは送らない。消すときはそのファイルを消す。

## 比較した案

環境変数が無いと残さない案は採らない。前回、入れなかったので実機の一回が消えた。いつもの起動で残す。
画面へ出す案は採らない。描画と混ざる。
操作を外へ送る案は採らない。製品の通信にしない。

## 影響と検証

保存の方針は [PRIVACY](../PRIVACY.md)。ジャンプの速度そのものは [ADR 0010](0010-jump-steer.md) のまま。
Swift Testing が、宛先の決定と、バイトと打鍵の文字化を見る。
PTY の起動確認は記録を切り、実機のファイルを消さない。
実機の中身は、施主がもう一度遊んでから読む。この判断の時点ではまだ無い。
復元とリサイズは未検査なので、TERM-001 は planned のまま。
