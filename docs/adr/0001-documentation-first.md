# ADR 0001 — 文書初期化と製品実装を分ける

Status: accepted
Date: 2026-11-01
Scope: 初期設定の技術判断

## 背景

施主は公開リポジトリと Cursor 向けの規約・ポリシー・アプローチ整備を依頼した。
兄弟には完成したゲームの要件、実測、運用権限がある。名前の置換だけでは事実と提案が混ざる。

## 判断

Swift / ANSI・純粋 Core・整数固定刻み・自動プレイ・MIT を初期方針とする。
規範を Summit 向けに短く再構成し、登山のメカニクスは設計案として明示する。
Cursor 固有のファイルは入口に絞り、エージェント共通 AGENTS と正本文書を共有する。
最初の CI は文書だけを検査し、製品コードが入ったら製品用ゲートへの移行を要求する。

## 比較した案

完成済み Bolt を fork して改名する案は採らない。不要な戦闘・旧要件・検証済みという誤解を持ち込むため。
文書に make check とだけ書いて実体を置かない案も採らない。現段階で走る小さな検査を用意する。

## 影響

Swift ソース、ツール版、配布物はまだない。製品規則は planned。
P0 で自分の版と検査を証明し、段階的に active にする。兄弟の証拠や権限を継承しない。
