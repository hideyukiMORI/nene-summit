# ADR 0007 — ジャンプを短くし、一部屋の読みと画面下の案内にする

Status: accepted
Date: 2026-11-01
Issue: #9
Scope: 設計案。施主の確定要件ではない。数値は施主の実測ではない。

## 背景

跳ぶと画面の上まで届き、足場の差が消える。
案内の文が山の上にあり、部屋が何を教えているか読めない。
施主は、公開されている登山アクションの動きと序盤の部屋の順番、および Bolt / Swarm の画面の置き方を見るよう求めた。

## 判断

全力のジャンプの高さは、体のおよそ 3 倍に収まる範囲へ `MotionPolicy` で下げる。
この文書へ式も数も写さない。ダッシュの長さは数セルのまま。
参照した作品の定数、部屋、名前、絵は製品へ写さない。

一部屋は一つの画面で、安全な床、危険より手前のチェックポイント、ジャンプでは越せない隙間、短い階段、頂上の順にする。
地形はここで新しく置く。攻略図の形は写さない。
[ADR 0006](0006-unattended-retry.md) の「右へ跳ぶだけ」は、隙間の手前では歩き、縁ではダッシュし、壁では蹴る案内が置き換える。
`advance` 以外の経路は足さない。

画面は山を先に描き、その下に帯を置く。題、ダッシュの印、キーの一行。
Bolt の帯と Swarm の見出し・値・下端のキーを、登山に必要なものだけへ縮めた。
スコア、残機、右の大きなパネルは置かない。

## 比較した案

跳ぶ高さを保って足場だけ下げる案は採らない。操作の感じが変わらない。
参照作品の面をマスに写す案は採らない。製品の地形は独自にする。
山の上に操作説明を残す案は採らない。足場が読めることを優先する。

## 影響と検証

Swift Testing が、全力ジャンプの高さが体の 2 倍から 4 倍のあいだであること、
チェックポイントが棘より手前にあり頂上はそれより高く、床の隙間が 3 マス以上であること、
無入力でその部屋を登頂できること、画面にダッシュの印と `q` があることを見る。
複数の部屋、先読み、復元、リサイズ、配布は残る。
