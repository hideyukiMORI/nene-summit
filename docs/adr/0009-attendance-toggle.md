# ADR 0009 — オートとマニュアルを m で切り替える

Status: accepted
Date: 2026-11-01
Issue: #13
Scope: 設計案。施主の確定要件ではない。

## 背景

キーを離すと案内が登り始める。立ち止まって狙う遊びと、放っておく登山を、同じ画面で選べない。
施主は、オートとマニュアルを何かのキーでトグルできるとよい、と提案した。

## 判断

起動時はオート。`m` の押し始めだけで、オートとマニュアルを切り替える。押しっぱなしでは連続して切り替わらない。
`m` は移動でもジャンプでもない。`Input` には入れない。

オートでは、これまでどおりキーが無い tick を案内が受け持つ。頂上のあとと、打ち切りのやり直しも残る。
マニュアルでは、キーが無い tick も人の `Input` のまま進める。案内は呼ばない。打ち切りもしない。
マニュアルで頂上に着いたあと、キーが無いあいだは登頂のまま待つ。キーがあれば、同じ部屋を最初からやり直す。

画面の下のキーの行に、今のモードと `m` を出す。オートは `AUTO`、マニュアルは `PLAY`。
状態を進める経路は `SummitState.advance` のまま。モードを持つのは呼び出し側と `Watch` の引数だけ。

## 比較した案

キーを離したら常に案内へ戻す案は採らない。マニュアルで立ち止まれない。
起動時をマニュアルにする案は採らない。放っておくと登る、がこの製品の始まりだから。
`t` を使う案は採らない。テーマの候補として残している。
モードを `Input` に混ぜる案は採らない。同じ入力列の物理が、モードで変わってしまう。

## 影響と検証

[ADR 0006](0006-unattended-retry.md) の「キーが無い tick は案内」は、オートのときの規則として残る。マニュアルは案内を呼ばない。

Swift Testing が、オートの無入力で登頂してやり直すこと、マニュアルの無入力でその場に留まること、
マニュアルの頂上は無入力のままであること、画面に `AUTO` と `PLAY` と `m` が出ること、
`m` が移動キーにならないことを見る。
PTY は起動のあと `q` だけ。復元とリサイズは未検査なので、TERM-001 は planned のまま。
実機で `m` を押した感触は未計測。
複数の部屋、先読み、テーマ、配布は残る。
