# ADR 0020 — 壁に沿って上る井戸を道に足す

Status: accepted
Date: 2026-11-01
Issue: #37
Scope: 設計案。施主は絵を足さず、仕組みのロジックを取り込むと定めた。井戸の幅と高さは施主の指定ではない。

## 背景

道は、ばね、横の床、上の床のあと、最初の部屋へ戻る。
公開の攻略は、その次を、左右の壁のあいだを蹴って上る井戸として書いている。
壁蹴り自体は既にある。案内の跳び方は部屋ごとに無い。

## 判断

井戸は左右が壁の細い縦穴で、頂上はその上にある。
新しい字形は足さない。壁は既存の固いマス、頂上は既存の頂上マス。
当たりも移動も `SummitState.advance` の中だけ。別の物理は足さない。
案内は [ADR 0017](0017-lookahead.md) の先読みのまま。この部屋のためだけの跳び方は足さない。
いまのジャンプで先読みが届く高さに収める。届かない段は、この変更では足さない。
道は上へ運ぶ床のあとこの井戸、そのあと最初の部屋へ戻る。隙間を間に置くのは [ADR 0022](0022-low-slot.md)。
作品の名前と絵は入れない。

## 比較した案

井戸の絵や専用の文字を足す案は採らない。[ADR 0019](0019-logic-not-pictures.md) が拒む。
先読みが届かない高さの穴を、部屋専用の案内で登らせる案は採らない。跳び方の置き場が二つになる。
壁の滑りや新しい蹴り速度を足す案は採らない。経路が二つになる。

## 影響と検証

[ADR 0018](0018-spring-and-deck.md) が残した井戸は、本決定が道へ足す。
Swift Testing が、無入力で井戸を登頂すること、その途中で壁に沿うこと、井戸のあと最初の部屋へ戻ることを見る。
さらに先の部屋、カメラの補間、テーマ、配布は残る。
実機で井戸の感触は未計測。
