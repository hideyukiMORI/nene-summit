# ADR 0006 — 無入力でも一部屋を登ってやり直す

Status: accepted
Date: 2026-11-01
Issue: #7
Scope: 設計案。施主の確定要件ではない。数値は施主の実測ではない。

右へ跳ぶだけの案内は [ADR 0007](0007-shorter-jump.md) が置き換えた。
キーが無い tick を常に案内へ渡すことは、オートのときに限る。[ADR 0009](0009-attendance-toggle.md) を見る。
無入力で `advance` だけを呼び、打ち切りで同じ部屋をやり直すことは、オートでは残る。
頂上のあとに同じ部屋へ戻すことは、道の上の部屋では [ADR 0014](0014-next-room.md) が置き換える。

## 背景

人がキーを離すと、画面の登山が止まる。
[ADR 0005](0005-playable-climb.md) は人が登る経路までで、放っておく遠征は残していた。

## 判断

案内は `Guide.choose` が `Input` を返すだけ。状態は `SummitState.advance` だけが進める。
登頂できないときのやり直しは `Watch.advance` が、同じ部屋の `SummitState.begin` を呼ぶ。
頂上のあとの続きは [ADR 0014](0014-next-room.md)。
キーが `idle` の tick は案内に任せ、それ以外の tick は人の `Input` が勝つ。
頂上のあとの間と、登頂できないときの打ち切りは `Watch` の定数。この文書へ写さない。
人の入力が続いているあいだは、打ち切りで遠征を取り上げない。
別の物理と外部の乱数は入れない。先読みは [ADR 0017](0017-lookahead.md) が、`advance` の複製だけで足す。

## 比較した案

実行ファイルに跳び方を書く案は採らない。案内の置き場が二つになる。
登れない部屋で同じセルを跳び続ける案は採らない。スクリーンセーバーが止まって見える。
人の操作中も打ち切る案は採らない。考えているあいだに最初へ戻る。

## 影響と検証

Swift Testing が、無入力での登頂、間のあと最初へ戻って再び登頂できること、
袋小路では打ち切りで最初へ戻ること、人の入力では打ち切らないことを見る。
この案内は右へ跳ぶ。別の部屋を解く保証ではない。
複数の部屋、テーマ、配布は残る。先読みは [ADR 0017](0017-lookahead.md)。
