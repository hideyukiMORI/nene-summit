# ADR 0012 — 方向を押したジャンプは斜め上へ進む

Status: accepted
Date: 2026-11-01
Issue: #19
Scope: 設計案。施主の確定要件ではない。数値は施主の実測ではない。

## 背景

操作の意図は、右上の浮島へ跳ぶこと。
[ADR 0010](0010-jump-steer.md) のあと、右を押したジャンプの横速度は走る速さになり、論理としては乗っている。
実機の記録では、その軌道はほぼ真上で、着地は数マス右、穴の中か手前の床だった。
浮島への移動になっていない。

## 判断

方向を押して跳ぶ tick は、上への速さと揃った横速度で斜めに出る。
空中でその方向を押し続けているあいだ、目標はその斜めの速さのまま。1 tick で届く。
方向を離した空中は、横の目標を 0 へ戻す。
方向を押さずに跳ぶ tick は、今の横速度を保つ。
地面を走る目標は、走る速さのまま。壁蹴りの横速度は変えない。
速さは `MotionPolicy` だけが持つ。この文書へ写さない。
経路は `SummitState.advance` のまま。

この部屋では、右を押した全力のジャンプを出発から二回続けると、下の浮島に着く。
方向を押さないジャンプは、隙間を越えない。

## 比較した案

走る速さのままにする案は採らない。記録では右上へ進んでいない。
隙間を狭めて、跳ぶ速さを変えない案は採らない。操作が右上へ動いていない。
人だけ斜めにして、案内は古い弧のまま、という第二の物理は採らない。

## 影響と検証

[ADR 0010](0010-jump-steer.md) の「空中は走る速さ」は、方向を押しているあいだは本決定が置き換える。
[ADR 0007](0007-shorter-jump.md) の隙間は、方向を押さないジャンプでは越せない、として残る。
Swift Testing が、斜めの横速度、空中の 1 tick、地面の走る速さ、二回の右ジャンプで下の浮島に着くこと、
無入力の登頂を見る。
頂上に触れたあとのやり直しは変えない。実機で右上へ跳んだ感触は未計測。
復元とリサイズは未検査なので、TERM-001 は planned のまま。
