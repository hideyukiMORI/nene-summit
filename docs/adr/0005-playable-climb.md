# ADR 0005 — 端末から一部屋を登り切れる

Status: accepted
Date: 2026-11-01
Issue: #5
Scope: 設計案。施主の確定要件ではない。数値は施主の実測ではない。

## 背景

人が端末で一部屋を走り、跳び、壁を蹴り、ダッシュし、棘で戻り、頂上に着き、`q` で終える。
[ADR 0004](0004-one-room-step.md) は位置を変えず、初期の向きを上にしていた。人が遊ぶには足りない。

## 判断

状態を進める経路は `SummitState.advance` のまま。`Replay.states` は `advance` だけを畳む。
倍率、体の大きさ、重力、走る速さ、跳ぶ速さ、壁蹴りの横速度、ダッシュの速さと長さは
`MotionPolicy` だけが持つ。この文書へ写さない。秒は Core に置かず、合成ルートに残す。

Y は上。範囲の外は固体。棘は固体ではなく、重なったら死ぬ。
同じ tick では跳ぶがダッシュに勝つ。ダッシュは接地へ入ったときだけ満タンに戻る。
初期の向きは右。床の上の `idle` は位置を変えない。左の世界端は壁蹴りのための壁。
開始セルは開いたマスかチェックポイント。棘より手前の歩く段にチェックポイントを置く。

部屋の絵は `FirstAscent.rows`。上の行が大きな Y。`@` は開いたマスであり、開始位置。
描画は Render がセルの枠を返し、Terminal が ANSI で塗る。
実行ファイルはキーを `Input` に写す。Glibc は Terminal だけが import する。
16 ミリ秒の待ちと、キーを押し続けたとみなす長さは合成ルートの方針であり、性能の保証ではない。

## 比較した案

この段階で自律登山を足す案は採らない。人が登れる経路が先だから。
物理の数を確定要件にする案は採らない。`MotionPolicy` は設計判断で、施主の実測ではない。
0004 の「位置を変えない」を残す案は採らない。人が動けない。

## 影響と検証

0004 の「位置を変えない」と「初期の向きは上」と「入力は idle と face だけ」は、この判断が置き換える。
`advance` が唯一の経路であることと、同じ入力列が同じ状態列になることは残る。

Swift Testing が、1 セルの壁で止まること、棘からチェックポイントへ戻ること、
着地でダッシュが戻ること、左の壁を蹴って右上へ離れること、著者の部屋を登頂できること、
同じ入力列の一致を見る。PTY は起動のあと `q` で終了コード 0 だけを見る。
終了後の termios 復元とリサイズは未検査なので、TERM-001 は planned のまま。
無入力のやり直しは [ADR 0006](0006-unattended-retry.md)。
複数の部屋、先読み、テーマ、配布は残る。
