# ADR 0024 — 画面に枠と奥行きと、拾う光を足す

Status: accepted
Date: 2026-11-01
Issue: #45
Scope: 施主は、参考画面の枠と上下の帯、奥の山と岩と光、触れると残るもの、夜明けの洞窟に寄せた色を求めた。色番号と光の名前は施主の指定ではない。

## 背景

帯も右の欄も同じ暗い地で、空は一枚だった。
枠は無く、触れて残るものも無い。
施主は、前よりよいが思っている画面ではない、と見た。

## 判断

地は黒。上も下も盤面も同じ黒にする。施主が地の色を黒にすると見た。
窓と右の欄の周りに、幅 1 の罫線を置く。床、棘、ばね、動く床、人は色面のまま。
奥の山はカメラより遅く、洞窟の岩は部屋に張り付く。きらめきは面にせず、小さな弱い光にして、欠けて消さない。いずれも描画だけ。乱数は使わない。当たりは変えない。
拾う光は部屋のマスである。踏んだことは `SummitState.advance` だけが記録する。落ちても、同じ部屋をやり直しても残る。次の部屋へは数だけを持ち、マスは持たない。
右の欄に数を出す。残機ではない。得点ではない。
色は夜明けの青、洞窟の紫、氷の光、人だけ暖色へ寄せる。数は `Painter`。この文書へ写さない。
作品の名前、果実の名前、図は入れない。

## 比較した案

仕組みごとに文字絵を足す案は採らない。[ADR 0019](0019-logic-not-pictures.md) のまま。
罫線を端末の幅を測ってから切り替える案は、計測がまだ無いので採らない。いまは幅 1 の罫線にする。倍幅になる端末は TERM-001 のまま未計測。
拾った数を部屋ごとに捨てる案は採らない。道を進んでも残した。
残機や得点を足す案は採らない。

## 影響と検証

仕組みの字形は足さない。画面の枠は施主が求めた。
[ADR 0023](0023-color-and-hud.md) では枠を見送っていた。施主が枠を求めたので、ここでは置く。
Swift Testing が、帯の地、枠、奥の遅れ、光を一度だけ拾うこと、落ちたあとも残ること、描画が状態を変えないことを見る。
実機の色と、罫線が幅 1 で出るかは未計測。
