# ADR 0010 — 跳ぶとき、押している左右が走る速さに乗る

Status: accepted
Date: 2026-11-01
Issue: #15
Scope: 設計案。施主の確定要件ではない。数値は施主の実測ではない。

## 背景

ジャンプと同時に `a` や `d` を押しても、横にほとんど進まない。
スペースを短く押すと、空中にいるあいだが足りず、横速度が乗る前に着地する。
施主は、ジャンプをシフトにしたら良くなるかを尋ねた。

## 判断

接地で方向を押したまま跳ぶ tick は、その方向へ出る。空中の目標の速さは [ADR 0012](0012-up-right-jump.md) が置き換えた。
方向を離して跳ぶ tick は、今の横速度を保つ。
壁蹴りの横速度は、これまでどおり。
経路は `SummitState.advance` のまま。シフトはジャンプにしない。

案内は平らな床を歩く。段と、同じ高さの棘では跳ぶ。
棘の上に体が出てから、空中でダッシュして越える。縁のダッシュと、壁の蹴りは残る。
同じ `advance` なので、人のジャンプを速くすると案内の弧も変わる。案内の選び方で部屋を登り切る。

## 比較した案

ジャンプキーをシフトにする案は採らない。シフトは修飾で、端末が単体の押下を送らないことがあり、`a` と一緒だと同じ文字に畳まれる。横に進まない原因はキーの種類ではなかった。
跳ぶ tick が今の横速度だけを保つ案は採らない。止まっている状態から方向と一緒に押すと、横が 0 のまま上へ飛ぶ。
人だけ速くして案内は古い弧のまま、という第二の物理は採らない。

## 影響と検証

Swift Testing が、方向を離して跳ぶと跳ぶ前の横速度が残ること、壁蹴り、無入力の登頂を見る。
方向を押したときの速さは [ADR 0012](0012-up-right-jump.md)。
実機でスペースと `a` / `d` を押した感触は未計測。
その記録は [ADR 0011](0011-input-trace.md)。復元とリサイズは未検査なので、TERM-001 は planned のまま。
複数の部屋、先読み、テーマ、配布は残る。
