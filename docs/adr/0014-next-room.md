# ADR 0014 — 頂上のあと次の部屋へ進む

Status: accepted
Date: 2026-11-01
Issue: #23
Scope: 設計案。施主の確定要件ではない。

## 背景

一部屋を登頂すると、同じ部屋の最初に戻る。
次の山が無く、スクリーンセーバーが一つの画面を繰り返す。

## 判断

道は `Trail` が持つ。開始は最初の部屋。頂上のあとは次の部屋。次の部屋の頂上のあとは、最初の部屋へ戻る。
道に無い部屋は、自分の開始へ戻る。
頂上の続きを選ぶのは `Watch`。状態は `SummitState.advance` だけが進める。
登頂できないときの打ち切りは、同じ部屋の開始へ戻す。ここは変えない。
マニュアルで頂上にいてキーが無いあいだは、留まる。キーが来たら次の部屋が始まる。
マスの印は `RoomSketch` が一つだけ読む。部屋の絵は `SecondPitch.rows`。
参照した作品の地形は写さない。物理の数は変えない。先読みは当時入れず、[ADR 0017](0017-lookahead.md) が複製だけで足した。

次の部屋は、隙間を越えてからチェックポイントに触れ、その先の棘を越え、短い階段を登って頂上に着く。
いまの案内の入力だけで登頂できる。別の部屋を解く保証にはしない。

## 比較した案

頂上のあとも同じ部屋へ戻す案は採らない。次の山が現れない。
次の部屋を実行ファイルだけが知っている案は採らない。続きを決める場所が二つになる。
新しい部屋のためだけに、別の跳び方を足す案は採らない。案内の置き場が二つになる。
参照作品の面をマスに写す案は採らない。

## 影響と検証

[ADR 0006](0006-unattended-retry.md) の「頂上のあと同じ部屋へ戻す」は、道の上の部屋では本決定が置き換える。
打ち切りで同じ部屋へ戻すことは残る。
Swift Testing が、道の順、道の外は留まること、次の部屋では隙間のあとにチェックポイントがあること、
無入力で次の部屋へ進んで登頂し、そのあと最初の部屋へ戻ることを見る。
さらに先の部屋、カメラ、テーマ、配布は残る。動く床とばねは [ADR 0018](0018-spring-and-deck.md)。先読みは [ADR 0017](0017-lookahead.md)。
復元とリサイズは未検査なので、TERM-001 は planned のまま。
実機で次の部屋を登った感触は未計測。
