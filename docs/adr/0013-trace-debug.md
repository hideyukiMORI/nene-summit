# ADR 0013 — 入力記録はデバッグ定数が真のときだけ書く

Status: accepted
Date: 2026-11-01
Issue: #21
Scope: 設計案。施主の確定要件ではない。

## 背景

[ADR 0011](0011-input-trace.md) は、いつもの起動でローカルファイルへ入力を書いていた。
実機の一回は読み、方向を押したジャンプの軌道を直した。
施主は、オンオフをデバッグモードの定数にして、いまはオフにするよう求めた。

## 判断

`PlayTrace.debug` が記録のスイッチ。いまの値は偽。
偽のあいだはファイルを作らない。環境変数では切り替えない。
真のときだけ、これまでのパスへ、同じ一行を書く。パスはこの型が持つ。この文書へ写さない。
開けないとき、書けなくなったあとは、記録なしで遊びを続ける。
物理は変えない。ネットワークへは送らない。

## 比較した案

いつもの起動で書き続ける案は採らない。調査のあと、施主がオフを求めた。
環境変数で切り替える案は採らない。スイッチはソースの定数一つにする。

## 影響と検証

[ADR 0011](0011-input-trace.md) の「起動のたびに書く」と環境変数は、本決定が置き換える。行の形と、真のときのファイルは残る。
Swift Testing が、定数が偽で `open` が記録を開かないことを見る。
PTY の起動確認は環境変数を触らない。
復元とリサイズは未検査なので、TERM-001 は planned のまま。
