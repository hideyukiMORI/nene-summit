# ADR 0021 — 画面の刻みは枠の残りだけ待つ

Status: accepted
Date: 2026-11-01
Issue: #39
Scope: 設計案。施主は、実機で動きが飛んで見えるので、処理を安定させ少しゆっくりにするよう求めた。ミリ秒は施主の指定ではない。

## 背景

合成ルートは、状態を進めて描いたあとに、固定の時間を必ず足していた。
描画が重い tick は長く、軽い tick は短い。端末がその差を塗り切れないと、体が飛んで見える。
[要件](../REQUIREMENTS.md) は、描画を間引いてゲーム速度を変えない、と置いている。

## 判断

1 tick につき、描画は 1 回。描かない tick をまとめて速くしない。
待ちは、tick の開始から測った枠の残りだけ。作業にかかった時間の上に、さらに固定の待ちを足さない。
枠を超えた tick は、遅れを取り戻すために次の tick をまとめない。次の枠は、その tick の開始から測り直す。
枠の長さは `FramePace` に置く。この文書へ写さない。秒は Core に置かない。
物理の速度は変えない。

## 比較した案

描画を数 tick に 1 回にする案は採らない。見えないあいだに体が進み、飛びが大きくなる。
作業時間にかかわらず同じ待ちを足す案は採らない。重い描画の tick だけ遅れる。
遅れを、描かない tick で取り戻す案は採らない。速さが揺れる。

## 影響と検証

[ADR 0005](0005-playable-climb.md) の「描いたあとに固定の時間を必ず待つ」は、本決定が置き換える。
Swift Testing が、使い始めた枠は全部待つこと、途中なら残りだけ待つこと、
枠を超えても遅れをまとめないこと、時計が戻っても枠を超えて待たないことを見る。
実機で、飛びが減った感触は未計測。復元とリサイズは未検査なので、TERM-001 は planned のまま。
