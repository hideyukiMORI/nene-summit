# ADR 0004 — 一部屋の状態は固定 tick の advance だけが進める

Status: accepted
Date: 2026-11-01
Issue: #3
Scope: 設計案。施主の確定要件ではない。

## 背景

P1 は Core の Input、State、Event、一部屋、初期位置、固定 tick を一つの経路にする。
同じ入力列から同じ状態列になること、不正な部屋を結果型で拒むことが受け入れ条件。
走る・跳ぶ・壁蹴り・ダッシュと、tick を秒へ対応させる倍率は、まだ測っていない。

## 判断

部屋の名前は `RoomId.make` だけが空文字を拒む。幅・高さ・初期位置は `Room.make` だけが拒む。
幅と高さは 1 以上。初期位置のセルは 0 以上かつ幅・高さ未満。負の座標は部屋の外として拒む。
セルは地形のマスであり、物理の固定小数点ではない。倍率は P2 で測ってから ADR にする。

開始状態は `SummitState.begin`。位置は部屋の初期位置、tick は 0、向きは上。
上を初期値にしたのは、登山の正面を一つに決めるため。入力が向きを変えるまで動かない。

`SummitState.advance` が一刻みの唯一の経路。tick は 1 だけ増える。位置は変えない。
入力は `idle` か `face`。`idle` の出来事は `.tick`。`face` は `.tick` のあとに `.faced`。
秒・時計・環境は合成ルートのまま、この段階では作らない。

入力列から状態列を作る関数は `Replay.states` だけで、中では `advance` だけを呼ぶ。

## 比較した案

この段階で重力と移動を入れる案は採らない。P2 の不変条件と倍率の実測がまだだから。
tick を秒に固定する案は採らない。未測の数を確定要件にしない。
向きを持たせず tick だけ進める案は採らない。入力の違いが状態に出ず、同じ列の検査が弱くなる。

## 影響と検証

Swift Testing が、拒否、初期状態、tick、位置が残ること、同じ列の一致、違う向きの分岐を見る。
物理、棘、チェックポイント、描画、端末は未実装。
