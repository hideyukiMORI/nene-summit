# ADR 0018 — ばねと動く床は advance の中で動く

Status: accepted
Date: 2026-11-01
Issue: #33
Scope: 設計案。施主は、公開の地図を見ながら部屋を足し、ばねと動く床も作るよう求めた。速さ、振幅、待ちは施主の指定ではない。

## 背景

道は二部屋だった。
公開の攻略は、初めを上へ弾く床、危険を横切る動く足場、上へ運ぶ足場として書いている。
ばねも動く床も、この山には無かった。

## 判断

ばねはマスである。重なると上へ弾き、ダッシュを満タンに戻す。固くはない。
動く床は `M` が横、`V` が上へ動く。位置は tick だけで決まる。
床の上に立っていれば、床と同じだけ体を運ぶ。遠い端で待ってから戻る。
当たりも運搬も、`SummitState.advance` の中だけ。別の物理は足さない。
速さ、振幅、待ちは `MotionPolicy` に置く。この文書へ写さない。
道は、いまの二部屋のあと、ばねの段、横に渡る床、上へ運ぶ床、そして最初へ戻る。
段の高さは、いまのジャンプでは届かず、ばねか床なら届く。
作品の名前と絵は部屋に入れない。案内の跳び方は部屋ごとに足さない。

## 比較した案

ばねを別の速度関数にする案は採らない。経路が二つになる。
動く床を毎 tick 地図へ焼き、戻す案は採らない。戻し忘れが先読みを壊す。
壁の井戸を同じ変更に入れる案は採らない。ばねと床だけで、登れるかを先に見る。

## 影響と検証

[ADR 0014](0014-next-room.md) の「動く床は残る」は、本決定が置き換える。道の順は長くなる。
Swift Testing が、ばねで上へ弾くこと、横の床と上の床が体を運ぶこと、
無入力で三部屋を登頂し、最後のあと最初へ戻ることを見る。
壁の井戸は [ADR 0020](0020-wall-well.md)。落ちる塊と崩れる床と結晶は [ADR 0028](0028-falling-traps.md)。
さらに先の部屋、カメラの補間、テーマ、配布は残る。
実機でばねと床の感触は未計測。
